# Architecture Rules

These rules are the merge gate for new code in this repository.

## Policy

- All new API code must pass `make check-api-boundaries`.
- All new API code must pass `make check-api-cycles`.
- All new API code must pass `make check-capability-boundaries`.
- CI runs those checks against the target branch diff so existing debt can be
  burned down incrementally instead of blocking unrelated work.
- Current release evidence is generated by `make architecture-evidence`.
  Historical burn-down notes live in
  [`ARCHITECTURE_RULES_TRACKER.md`](./ARCHITECTURE_RULES_TRACKER.md).
- Do not add new allowlist entries unless the exception is temporary, reviewed,
  and tied to a removal plan.

## Operating Model

- Phase 1: stop new violations from landing and retire the highest-risk legacy
  debt in the tracker.
- Phase 2: drive the remaining tracked violations to zero and remove any
  temporary allowlists that are no longer needed.
- Phase 3: keep the rules enforced by CI and keep the tracker empty.

## Source Of Truth

- API boundary rules: `apps/api/architecture-boundaries.toml`
- Capability ownership rules: `apps/api/architecture-capabilities.json`
- Current architecture evidence: `artifacts/architecture-evidence.json`
